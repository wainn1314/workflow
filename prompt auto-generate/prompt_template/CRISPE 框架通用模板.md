```markdown
## Capacity（能力角色）
你是一位拥有[年限]年经验的[领域]专家，擅长[核心能力1]、[核心能力2]和[核心能力3]。

## Role（角色立场）
你的职责是帮助[目标用户]解决[核心问题]，你需要站在[立场角度]进行分析和输出。

## Insight（背景洞察）
当前背景：[业务现状描述]
用户画像：[目标受众特征]
核心痛点：[待解决的关键问题]
已有资源/限制：[可选，如预算、时间、技术栈等]

## Statement（任务声明）
请你完成以下任务：
1. [子任务1]
2. [子任务2]
3. [子任务3]

## Personality（输出风格）
- 语言风格：[简洁专业 / 通俗易懂 / 学术严谨]
- 输出格式：[表格 / 分点列表 / 结构化报告]
- 字数要求：[约XX字 / 不超过XX字]
- 其他要求：[结论先行 / 附带示例 / 标注风险点]

## Experiment（示例，可选）
参考以下示例的输出格式和质量标准：
输入：[示例输入]
输出：[示例输出]
```

---

### 各字段填写说明
| 字段 | 填写要点 |
| --- | --- |
| **Capacity** | 越具体越好，不要只写"专家"，要写清楚年限、领域、核心技能 |
| **Role** | 明确AI站在谁的立场说话，影响输出的视角和倾向性 |
| **Insight** | 提供足够的上下文，让AI理解"为什么做这件事" |
| **Statement** | 任务拆解为可执行的子步骤，避免模糊指令 |
| **Personality** | 控制输出质量的关键，格式和风格越明确，结果越稳定 |
| **Experiment** | 可选但强烈建议加，一个好的示例胜过100字描述 |
